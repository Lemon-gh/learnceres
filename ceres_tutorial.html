01简介与核心概念

Ceres 用于求解带边界约束、经鲁棒化处理（robustified）的非线性最小二乘问题：

minx   ½ ∑i ρi( | fi(xi₁, …, xik) |² )
s.t.   lj ≤ xj ≤ uj

这类问题广泛出现在科学与工程领域：从统计学中的曲线拟合，到计算机视觉中从照片重建三维模型（Bundle Adjustment）。当 ρi(x)=x（恒等函数）且边界为无穷时，就退化为最常见的标准非线性最小二乘：½ ∑ |fi|²。

三个核心术语

ResidualBlock

残差块

由一个代价函数 fi 和它依赖的若干参数块构成，是问题的基本组成单元。

ParameterBlock

参数块

一组一起出现的小标量，如相机的 3 维平移向量、四元数的 4 个分量；单个标量也可以是一个参数块。

LossFunction

损失函数

标量函数 ρi，用于降低离群点（outlier）对解的影响，实现鲁棒拟合。

学习主线

无论示例多复杂，用 Ceres 解题永远是四步：① 定义代价函数（残差）→ ② 构建 Problem 并添加残差块 → ③ 配置 Solver::Options → ④ 调用 Solve()。后面的每个示例都是这条主线的具体化。

02Hello World：最简单的问题

先求函数 ½(10 − x)² 的最小值，最优解显然是 x = 10。这是展示 Ceres 基本流程的最佳起点。

第一步：写残差仿函数（functor）

cost_functor.h · 自动微分版
struct CostFunctor {
  template <typename T>
  bool operator()(const T* const x, T* residual) const {
    residual[0] = T(10.0) - x[0];
    return true;
  }
};
关键点：为什么用模板？

operator() 是模板方法，所有输入输出都是类型 T。Ceres 在只需残差值时用 T = double 调用它；在需要雅可比矩阵时用特殊类型 T = Jet 调用——这就是自动微分的魔法所在。

第二步：构建问题并求解

helloworld.cc
#include "ceres/ceres.h"
#include "glog/logging.h"
using ceres::AutoDiffCostFunction;
using ceres::CostFunction;
using ceres::Problem;
using ceres::Solver;
using ceres::Solve;

int main(int argc, char** argv) {
  google::InitGoogleLogging(argv[0]);

  double x = 0.5;                 // 待求变量及其初值，求解器会原地修改它
  const double initial_x = x;

  Problem problem;                // 构建问题
  CostFunction* cost_function =
      new AutoDiffCostFunction<CostFunctor, 1, 1>(); // 1 残差, 1 参数
  problem.AddResidualBlock(cost_function, nullptr, &x);

  Solver::Options options;        // 配置并运行求解器
  options.minimizer_progress_to_stdout = true;
  Solver::Summary summary;
  Solve(options, &problem, &summary);

  std::cout << summary.BriefReport() << "\n";
  std::cout << "x : " << initial_x << " -> " << x << "\n";
  return 0;
}

模板参数 AutoDiffCostFunction<CostFunctor, 1, 1> 依次表示：残差块类型、残差维度（1）、每个参数块的维度（1）。

iter cost cost_change |gradient| |step| tr_ratio tr_radius 0 4.512500e+01 0.00e+00 9.50e+00 0.00e+00 0.00e+00 1.00e+04 1 4.511598e-07 4.51e+01 9.50e-04 9.50e+00 1.00e+00 3.00e+04 2 5.012552e-16 4.51e-07 3.17e-08 9.50e-04 1.00e+00 9.00e+04 Ceres Solver Report: Iterations: 2, Initial cost: 4.512500e+01, Final cost: 5.012552e-16, Termination: CONVERGENCE x : 0.5 -> 10

从 x=0.5 出发，两次迭代即收敛到 x=10。这是线性问题，理论上一次线性求解即可；示例未改默认配置，因为默认参数是为更难的非线性问题设计的。

03导数计算：三种方式怎么选？

Ceres 需要在任意参数值处计算目标函数每一项的值和导数。它提供三种求导方式：

方式适用场景推荐度
AutoDiffCostFunction
自动微分		残差能写成模板仿函数（绝大多数情况）。利用 C++ 模板与 Jet 类型，链式法则精确求导，效率与精度俱佳。★★★★★ 首选
NumericDiffCostFunction
数值微分		残差计算依赖无法修改的库函数，无法写成模板时使用（有限差分近似）。★★ 谨慎
CostFunction 子类
解析导数		需要手工推导雅可比，且闭式解比自动微分更高效，或使用近似导数时。★★★ 特殊场景

数值微分示例

numeric_diff.cc
struct NumericDiffCostFunctor {
  bool operator()(const double* const x, double* residual) const {
    residual[0] = 10.0 - x[0];
    return true;
  }
};
CostFunction* cost_function =
    new NumericDiffCostFunction<NumericDiffCostFunctor,
                               ceres::CENTRAL, 1, 1>();
problem.AddResidualBlock(cost_function, nullptr, &x);
官方建议

优先使用自动微分。数值微分计算昂贵、易受数值误差影响，还会导致收敛变慢；只有在确实无法使用模板时才退而求其次。

解析微分示例

analytic_diff.cc
class QuadraticCostFunction : public ceres::SizedCostFunction<1, 1> {
 public:
  virtual ~QuadraticCostFunction() {}
  virtual bool Evaluate(double const* const* parameters,
                        double* residuals,
                        double** jacobians) const {
    const double x = parameters[0][0];
    residuals[0] = 10 - x;
    if (jacobians != nullptr && jacobians[0] != nullptr) {
      jacobians[0][0] = -1;   // 残差是线性的，雅可比为常数 -1
    }
    return true;
  }
};

Evaluate() 中 jacobians 是可选输出：仅在非空时才需要计算对应雅可比（参数块被设为常量时会跳过）。尺寸在编译期已知时继承 SizedCostFunction，否则继承 CostFunction。

更多高级方式

当参数块数量或尺寸在编译期未知时，可用 DynamicAutoDiffCostFunction；此外还有 CostFunctionToFunctor、ConditionedCostFunction 等。

04Powell 函数：多参数与稀疏依赖

Powell 函数有 4 个变量和 4 个残差，目标是最小化 ½‖F(x)‖²。它的价值在于展示：每个残差块只声明它真正依赖的参数，而不是把所有参数一股脑塞进去——这让 Ceres 能利用问题的稀疏结构。

F4 残差 · powell.cc
struct F4 {
  template <typename T>
  bool operator()(const T* const x1, const T* const x4,
                  T* residual) const {
    residual[0] = sqrt(10.0) * (x1[0] - x4[0]) * (x1[0] - x4[0]);
    return true;
  }
};
构建问题
double x1 = 3.0, x2 = -1.0, x3 = 0.0, x4 = 1.0;
Problem problem;
problem.AddResidualBlock(
    new AutoDiffCostFunction<F1, 1, 1, 1>(), nullptr, &x1, &x2);
problem.AddResidualBlock(
    new AutoDiffCostFunction<F2, 1, 1, 1>(), nullptr, &x3, &x4);
problem.AddResidualBlock(
    new AutoDiffCostFunction<F3, 1, 1, 1>(), nullptr, &x2, &x3);
problem.AddResidualBlock(
    new AutoDiffCostFunction<F4, 1, 1, 1>(), nullptr, &x1, &x4);

注意 F1 只依赖 x1,x2，F4 只依赖 x1,x4。求解结果 x ≈ (0, 0, 0, 0)，目标函数值降到约 1.12×10⁻¹⁵。

05曲线拟合：从无约束优化到数据拟合

现在做一个真正的数据拟合问题。数据由曲线 y = e^(0.3x + 0.1) 加上标准差 σ = 0.2 的高斯噪声生成，我们要拟合模型 y = e^(mx + c) 中的 m, c。

curve_fitting.cc
struct ExponentialResidual {
  ExponentialResidual(double x, double y) : x_(x), y_(y) {}

  template <typename T>
  bool operator()(const T* const m, const T* const c,
                  T* residual) const {
    residual[0] = y_ - exp(m[0] * x_ + c[0]);
    return true;
  }
 private:
  const double x_, y_;   // 一组观测样本
};

double m = 0.0, c = 0.0;
Problem problem;
for (int i = 0; i < kNumObservations; ++i) {
  CostFunction* cost_function =
      new AutoDiffCostFunction<ExponentialResidual, 1, 1, 1>(
          data[2*i], data[2*i + 1]);
  problem.AddResidualBlock(cost_function, nullptr, &m, &c);
}

每个观测点对应一个残差块，所有残差块共享同一组参数 m, c。拟合结果：

Initial m: 0 c: 0 Final m: 0.291861 c: 0.131439 // 真值 m=0.3, c=0.1

由于数据含噪声，结果偏离真值是正常的。有意思的是：在真值 (0.3, 0.1) 处评估目标函数得到 1.082425，反而比拟合结果的 1.05675 更差——这正是噪声数据在最小二乘意义下的体现。

06鲁棒曲线拟合：用损失函数抑制离群点

当数据中混入离群点时，普通最小二乘会被少数异常值严重拉偏。解决方法是给残差块挂一个 LossFunction：它对高残差（通常是离群点）降权，从而减弱其对解的影响。

普通 vs 鲁棒 · robust_curve_fitting.cc
// 普通最小二乘：nullptr 表示平方损失
problem.AddResidualBlock(cost_function, nullptr, &m, &c);

// 鲁棒拟合：Cauchy 损失，0.5 为尺度参数
problem.AddResidualBlock(cost_function, new CauchyLoss(0.5), &m, &c);

只改一个参数，拟合曲线就明显更接近真实的 ground-truth 曲线。Ceres 还内置 HuberLoss、SoftLOneLoss、ArctanLoss 等，可根据离群程度选择。

直觉理解

平方损失 r² 随残差二次增长，一个远离的点会产生巨大梯度把解拽过去；Cauchy 等鲁棒损失在残差大时增长趋于平缓，相当于告诉求解器“这个点可能是噪声，别太当真”。

07Bundle Adjustment：Ceres 的杀手级应用

Bundle Adjustment（光束法平差）是三维重建与视觉 SLAM 的核心：给定特征点观测与对应关系，同时优化三维点坐标和相机参数，最小化重投影误差。Ceres 的设计初衷之一就是高效求解这类大规模稀疏问题。

BAL 数据中每个残差依赖一个三维点和一个 9 参数相机：3 个旋转（轴角）、3 个平移、1 个焦距、2 个径向畸变。

重投影误差 · simple_bundle_adjuster.cc
struct SnavelyReprojectionError {
  SnavelyReprojectionError(double observed_x, double observed_y)
      : observed_x(observed_x), observed_y(observed_y) {}

  template <typename T>
  bool operator()(const T* const camera, const T* const point,
                  T* residuals) const {
    // camera[0,1,2] 为轴角旋转
    T p[3];
    ceres::AngleAxisRotatePoint(camera, point, p);
    // camera[3,4,5] 为平移
    p[0] += camera[3]; p[1] += camera[4]; p[2] += camera[5];

    // 畸变中心（Bundler 相机坐标系 z 轴为负，故取反号）
    T xp = -p[0] / p[2];
    T yp = -p[1] / p[2];
    const T& l1 = camera[7], &l2 = camera[8];
    T r2 = xp*xp + yp*yp;
    T distortion = 1.0 + r2 * (l1 + l2 * r2);

    const T& focal = camera[6];
    T predicted_x = focal * distortion * xp;
    T predicted_y = focal * distortion * yp;
    residuals[0] = predicted_x - T(observed_x);
    residuals[1] = predicted_y - T(observed_y);
    return true;
  }

  static ceres::CostFunction* Create(double x, double y) {
    return new ceres::AutoDiffCostFunction<SnavelyReprojectionError,
                                          2, 9, 3>(x, y);
  }
  double observed_x, observed_y;
};

这个残差手推雅可比相当繁琐，而自动微分让实现变得简洁——这正是 AutoDiff 在复杂模型中的价值。AngleAxisRotatePoint() 等函数来自 ceres/rotation.h。

组装与求解
ceres::Problem problem;
for (int i = 0; i < bal_problem.num_observations(); ++i) {
  ceres::CostFunction* cost_function =
      SnavelyReprojectionError::Create(
          bal_problem.observations()[2*i], bal_problem.observations()[2*i+1]);
  problem.AddResidualBlock(cost_function, nullptr /* squared loss */,
      bal_problem.mutable_camera_for_observation(i),
      bal_problem.mutable_point_for_observation(i));
}

ceres::Solver::Options options;
options.linear_solver_type = ceres::DENSE_SCHUR;  // BA 专用 Schur 求解器
options.minimizer_progress_to_stdout = true;
ceres::Solver::Summary summary;
ceres::Solve(options, &problem, &summary);

对于大规模稀疏问题可先尝试 SPARSE_NORMAL_CHOLESKY；而 BA 具有特殊的稀疏结构，Ceres 提供专门的 Schur 互补求解器（如 DENSE_SCHUR、SPARSE_SCHUR），通常快得多。

08进阶：Pose Graph SLAM

SLAM 即在未知环境中建图并同时定位。位姿图（pose graph）把问题抽象成：节点表示机器人位姿，边表示两节点间的相对变换（由里程计、激光扫描匹配等测得）。官方示例覆盖 2D 与 3D 两种。

2D Pose Graph

位置 + 朝向角

状态 x=[pᵀ, ψ]ᵀ，残差含平移差与归一化角度差；用 AngleManifold 处理角度的周期性，并对残差乘测量协方差逆平方根 Σ^(-1/2)。

3D Pose Graph

位置 + 四元数

状态 x=[pᵀ, qᵀ]ᵀ，用 Eigen 的 QuaternionManifold 保证更新只作用在流形切空间；注意 Eigen 四元数内存布局是 [x,y,z,w]，实部在最后。

流形（Manifold）的引入
problem.AddParameterBlock(parameters[i], 4,
                          new ceres::EigenQuaternionManifold());
// 角度、四元数等具有周期性/单位约束的量，必须声明流形，
// 否则更新会破坏其数学约束（如四元数不再是单位长度）。

示例程序读取 g2o 格式数据集，输出 poses_original.txt 与 poses_optimized.txt，并附带 plot_results.py 可视化优化前后的轨迹差异。

何时必须用 Manifold？

只要参数本身带有约束（角度 modulo 2π、四元数单位长度、旋转矩阵正交性），就应通过 AddParameterBlock 指定对应的 Manifold，让求解器在切空间内更新。

09编译与运行

10最佳实践与资源

优先使用自动微分

把残差写成模板仿函数，让 Ceres 用 Jet 自动求导；仅在必要时才用数值或解析导数。

正确声明参数依赖

每个残差块只传入它真正依赖的参数块，充分利用稀疏性，大幅提高大规模问题的求解速度。

有离群点就上鲁棒损失

数据不干净时，给 AddResidualBlock 挂 CauchyLoss / HuberLoss，避免被异常值带偏。

带约束的参数用 Manifold

角度、四元数等必须通过 Manifold 更新，保证参数始终满足其数学约束。

按问题规模选线性求解器

小规模用 DENSE_QR；大规模稀疏用 SPARSE_NORMAL_CHOLESKY；BA 类问题用 Schur 系列。

更多官方示例
