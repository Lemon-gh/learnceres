01最小二乘直觉

假设有一堆观测点，你想找一条直线 y = mx + c 穿过它们。怎么算“最好的”那条线？做法是：对每个点算出它到直线的残差 r（竖直距离），把所有残差平方后求和，让这个总和最小。

cost(m, c) = ½ ∑i ( yi − (m·xi + c) )²  →  求使其最小的 m, c

为什么平方？ 残差有正有负，直接相加会抵消；平方后非负，且大误差惩罚更重。为什么乘 ½？ 只为求导时和平方产生的 2 约掉，不影响最优解。

02仿函数：把结构体当函数用

普通函数写成 double f(double x){ return 10-x; }。而“仿函数”是一个定义了 operator() 的结构体，可以像函数一样调用：

functor_basics.cc
struct Minus {
  double operator()(double x) const { return 10.0 - x; }
};
int main() {
  Minus minus;                  // 造一个对象
  return minus(3.0) == 7.0;     // 像函数一样调用 → 7
}

Ceres 偏爱仿函数，因为它是对象，能携带数据。拟合时每个观测点 xᵢ,yᵢ 不同，可以构造时存进对象：

带状态的仿函数 · Ceres 代价函数的雏形
struct LineResidual {
  LineResidual(double x, double y) : x_(x), y_(y) {}
  double operator()(double m, double c) const {
    return y_ - (m * x_ + c);       // 残差
  }
 private:
  double x_, y_;
};
要点

operator() 末尾的 const 表示不修改对象自身，Ceres 的代价函数都带它。

03模板：一份代码，两种用途

把上面仿函数里的 double 换成类型参数 T，就得到模板：

template_basics.cc
template <typename T>
T minus(T x) { return T(10.0) - x; }

// 编译器自动生成两个版本：
// minus<double>(3.0) → 7.0    普通算术
// minus<Jet>(...)         自动带出导数

关键在 T(10.0)：把常量也构造成类型 T，让整个表达式都在 T 下运算。这正是 Ceres 自动微分的原理：

T = double

算残差

普通计算，得到残差数值，用来评估“当前误差多大”。

T = Jet

算导数

Ceres 的特殊类型，运算时顺带把导数算出，告诉求解器往哪调参数。

Ceres 标准代价函数写法
struct CostFunctor {
  template <typename T>
  bool operator()(const T* const x, T* residual) const {
    residual[0] = T(10.0) - x[0];   // 注意 T(10.0)
    return true;
  }
};
新手常踩的坑

把 T(10.0) 写成裸 10.0，或对 Jet 用 std::sin（应改为 ceres::sin），会让自动微分失效或编译报错。

04指针：让求解器改你的变量

Ceres 求解时会原地修改你传进去的参数，所以必须传地址：

pointer_basics.cc
void setToTen(double* p) { *p = 10.0; }   // *p 是那个变量本身
int main() {
  double x = 5.0;
  setToTen(&x);                 // &x 取地址
  // 此时 x == 10
}

若写成传值 setToTen(double p)，改的只是副本，外面的 x 不变。Ceres 内部同理：

Ceres 中传局部变量的地址
double x = 0.5;
problem.AddResidualBlock(cost_function, nullptr, &x);
Solve(options, &problem, &summary);
// 求解后 x 已被就地改成 ≈10
类比

&x 是把你家的地址给别人，他才能进屋改东西；传值只给了张照片，改照片不影响你家。

06自检：基础打好了吗

  2. 仿函数比普通函数多了什么能力？
  3. 为什么代价函数要写成 template<typename T>？
  4. AddResidualBlock(..., &x) 为什么传 &x？
  5. AutoDiffCostFunction<F, 1, 1> 两个 1 分别是什么？
点开参考答案
  1. 残差是预测值与观测值之差；平方消除正负抵消并加重大误差惩罚。
  2. 仿函数是对象，能用成员变量保存观测数据。
  3. 让 Ceres 用 double 算残差、用 Jet 算导数；写死 double 就得手推雅可比。
  4. 传地址才能让求解器原地修改 x，传值只改副本。
  5. 第一个是残差维度，第二个是参数块维度。

07原理深挖：最小二乘怎么解出来的

MATH + ANIMATION

前面你用滑块"感受"了 cost。现在回答一个更本质的问题：最优的 m, c 到底怎么算？Ceres 内部又用什么办法找到它？

① 把问题写成数学

要最小化 cost(m,c) = ½ Σ (yᵢ − (m·xᵢ + c))²。这是关于 m、c 的二次函数，图像是一个"碗"。碗底就是最优解。

② 求偏导并令其为零

∂cost/∂m = −Σ xᵢ (yᵢ − m·xᵢ − c) = 0 ∂cost/∂c = −Σ (yᵢ − m·xᵢ − c) = 0

令两个偏导为 0，整理后得到一个二元一次方程组，叫正规方程（Normal Equations）：

(Σxᵢ²)·m + (Σxᵢ)·c = Σxᵢyᵢ (Σxᵢ)·m + (n)·c = Σyᵢ

解这个方程组就得到闭式解 m*、c*（也就是你点"跳到最优解"时发生的事）。线性最小二乘能一步算出答案，不需要迭代。

③ 但 Ceres 面对的往往是非线性的

当模型是 y = e^(mx+c) 这种，正规方程不再有闭式解。Ceres 改用迭代下降：从初值出发，沿 cost 的负梯度方向一小步一小步挪到碗底。梯度就是偏导组成的向量：

∇cost = [ ∂cost/∂m , ∂cost/∂c ]ᵀ   →   更新：(m,c) ← (m,c) − α·∇cost
动画演示 · 从初值沿梯度下降到碗底

灰色椭圆是 cost 的等高线（越靠内 cost 越低）。红点是当前参数，沿负梯度一步步走向中心的绿色最优点。调学习率 α 看收敛快慢——太大反而会在碗里来回震荡。

关键认知

Ceres 的 Solver::Solve() 干的就是这件迭代下降的事，只是它用的是更聪明的高斯-牛顿 / LM 算法（下一阶段详述），比纯梯度下降快得多。而每一步的方向（梯度 / 雅可比），正是靠自动微分算出来的（阶段 3 详述）。
