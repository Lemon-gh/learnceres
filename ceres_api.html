Ceres Solver API 使用手册

系统梳理 Ceres 的核心 API：从建模容器 Problem、代价函数家族、鲁棒损失与流形，到求解配置 Solver::Options 与结果 Solver::Summary。每个接口都给出真实签名、参数说明和可直接用的示例代码。

01API 总览：一张图看懂各司其职

用 Ceres 解题，本质上就是把"要优化什么、误差怎么算、怎么求解"这三件事分别交给几个对象。搞清楚它们的分工，再看每个 API 就顺了。

(AutoDiff 包装)→ Problem

建模

ceres::Problem

装参数块和残差块的容器。你告诉它"哪些量要求、每个误差怎么算"，它组织成优化问题。

残差

CostFunction 家族

定义残差怎么算、雅可比怎么来。常用 AutoDiffCostFunction，写公式即可自动求导。

鲁棒

LossFunction 家族

可选。给残差套一层鲁棒损失（Huber/Cauchy），抑制离群点。不传就是普通平方损失。

约束

Manifold 家族

可选。约束参数活在流形上（如单位四元数、角度周期），更新时自动投影回合法空间。

配置

Solver::Options

求解器的所有旋钮：用哪种线性求解器、迭代上限、收敛精度、线程数、是否打印日志。

结果

Solver::Summary

求解后拿它看结果：收敛没有、初末 cost、迭代次数、各阶段耗时、完整报告。

头文件速查

#include "ceres/ceres.h" 是最省事的写法，它已经包含了 problem、cost_function、solver、loss_function、manifold 等常用头文件。细分头文件如 ceres/problem.h、ceres/autodiff_cost_function.h 按需引入。

02求解入口：ceres::Solve()

所有求解都从这一个全局函数开始。它把配置、问题、结果三者串起来。

void Solve(const Solver::Options& options, Problem* problem, Solver::Summary* summary);
参数说明
options输入。求解配置，决定用什么算法、迭代多久、精度多少。
problem输入/输出。你构建的问题；求解后其中的参数块会被原地修改为最优值。
summary输出。求解过程的统计与诊断信息。
最小调用骨架
ceres::Problem problem;
// ... 向 problem 添加残差块 ...

ceres::Solver::Options options;
options.max_num_iterations = 100;
options.linear_solver_type = ceres::DENSE_QR;
options.minimizer_progress_to_stdout = true;

ceres::Solver::Summary summary;
ceres::Solve(options, &problem, &summary);

std::cout << summary.BriefReport() << std::endl;
注意

Solve 是同步阻塞的，返回时参数已经更新完毕。参数块必须是有效的 double*，且在整个求解期间保持内存有效。

03Problem：建模容器

ceres::Problem 是你搭优化问题的主战场。核心就两件事：加参数块、加残差块。其余接口多用于精细控制和诊断。

3.1 AddResidualBlock — 添加残差块（最核心）

// 最常用：直接列出各参数块的指针（最多 10 个） template<typename... Ts> ResidualBlockId AddResidualBlock(CostFunction* cost_function, LossFunction* loss_function, double* x0, Ts*... xs); // 用 vector 传参数块 ResidualBlockId AddResidualBlock(CostFunction*, LossFunction*, const std::vector<double*>& parameter_blocks); // 用数组 + 数量传参数块 ResidualBlockId AddResidualBlock(CostFunction*, LossFunction*, double* const* const parameter_blocks, int num_parameter_blocks);
参数说明
cost_function定义残差怎么算。它自带"期望的参数块尺寸"信息，Ceres 会校验与传入参数块是否匹配。
loss_function鲁棒损失。传 nullptr 表示普通平方损失；传 new ceres::CauchyLoss(...) 等做鲁棒拟合。
x0, xs...这个残差依赖的参数块指针。只传它真正依赖的，别偷懒全传。
所有权：Problem 默认接管 cost_function 和 loss_function，析构时只 delete 一次——所以同一个 cost_function 对象可以安全复用到多个残差块。若想自己管理生命周期，用 Problem::Options 里的 ownership 枚举。
隐式添加：参数块没显式 AddParameterBlock 也会在这里被自动加进去。显式加只是为了多一层尺寸检查。

3.2 AddParameterBlock — 显式添加参数块

void AddParameterBlock(double* values, int size); void AddParameterBlock(double* values, int size, Manifold* manifold);

什么时候需要显式调用？当你想给参数块绑定流形（见第 06 章），或想让 Ceres 提前做尺寸校验时。同一指针重复调用相同参数会被忽略；相同指针不同 size 会直接崩溃。

3.3 SetManifold — 给参数块绑定流形

void SetManifold(double* values, Manifold* manifold); // Ceres 2.2 起，旧的 SetParameterization(LocalParameterization*) 已弃用
给四元数和角度绑定流形
double q[4] = {0, 0, 0, 1};        // 单位四元数
double angle[1] = {0.0};           // 角度
problem.AddParameterBlock(q, 4);
problem.AddParameterBlock(angle, 1);
problem.SetManifold(q, new ceres::EigenQuaternionManifold());
problem.SetManifold(angle, new ceres::AngleManifold());

3.4 固定 / 释放参数块

void SetParameterBlockConstant(const double* values); // 固定，不参与优化 void SetParameterVariable(double* values); // 恢复可变 bool IsParameterBlockConstant(const double* values) const;

标定场景常用来固定某些已知量：比如已知相机内参时把它设为常量，只优化外参。

3.5 参数边界约束

void SetParameterLowerBound(double* values, int index, double lower_bound); void SetParameterUpperBound(double* values, int index, double upper_bound);
把某参数限制在 [0.1, 10]
double focal[1] = {1.0};
problem.SetParameterLowerBound(focal, 0, 0.1);
problem.SetParameterUpperBound(focal, 0, 10.0);
边界 + 流形冲突

一个参数块如果绑定了 Manifold，通常不要再设上下界——二者语义冲突，Ceres 会报错。需要约束流形参数请用专门的流形类型。

3.6 诊断与查询接口

接口用途
NumParameterBlocks() / NumResidualBlocks() / NumParameters()统计参数块数 / 残差块数 / 标量参数总数。
HasParameterBlock(const double*)判断指针是否已是参数块。
ParameterBlockTangentSize(const double*)参数块的切空间维度（流形下可能小于 size）。
RemoveResidualBlock(ResidualBlockId)移除残差块。
RemoveParameterBlock(const double*)移除参数块及依赖它的残差。
Evaluate(...)求解后手动计算残差、梯度、雅可比（做数值校验时很有用）。
智能剪枝

Ceres 会自动分析依赖关系，只求解真正影响自由参数的子问题。比如 100 万个参数块里只有一个可变、只有 10 个残差依赖它，计算量就等同于只有 1 个参数块和 10 个残差——所以不必手动拆问题。

04CostFunction 家族：定义残差与导数

这一族回答两个问题：残差怎么算，以及雅可比（导数）从哪来。不同子类就是导数来源不同。实际项目里绝大多数用 AutoDiffCostFunction。

4.1 CostFunction — 抽象基类

class CostFunction { virtual bool Evaluate(double const* const* parameters, double* residuals, double** jacobians) const = 0; virtual int NumResiduals() const = 0; };

这是所有代价函数的基类。parameters 是各参数块的数组，residuals 输出的残差向量，jacobians 输出的雅可比（可能为 nullptr，表示这次不要雅可比）。直接继承它意味着手写解析雅可比。

4.2 SizedCostFunction — 固定尺寸 + 手写雅可比

template<int kNumResiduals, int... ParameterBlockSizes> class SizedCostFunction : public CostFunction; // 只需实现 Evaluate，维度由模板参数给定 virtual bool Evaluate(double const* const* parameters, double* residuals, double** jacobians) const;
手写雅可比示例：残差 = x² − y
struct MyCost : ceres::SizedCostFunction<1, 1, 1> {
  bool Evaluate(double const* const* params, double* residuals,
                double** jacobians) const override {
    double x = params[0][0], y = params[1][0];
    residuals[0] = x*x - y;
    if (jacobians) {
      if (jacobians[0]) jacobians[0][0] = 2*x;   // ∂r/∂x
      if (jacobians[1]) jacobians[1][0] = -1;    // ∂r/∂y
    }
    return true;
  }
};
适用：对性能极致敏感、且能轻松写出正确导数的场景。缺点是导数极易写错且难维护。

4.3 AutoDiffCostFunction — 自动微分（首选）

template<typename CostFunctor, int kNumResiduals, int... ParameterBlockSizes> class AutoDiffCostFunction : public SizedCostFunction<kNumResiduals, ParameterBlockSizes...>; // 构造 AutoDiffCostFunction(CostFunctor* functor, Ownership ownership = TAKE_OWNERSHIP);

只要写一个带模板 operator() 的仿函数，Ceres 用前向模式自动微分同时算出残差和雅可比。模板参数三个数依次是：残差维度、各参数块维度。

残差 2 维，两个参数块分别 9 维和 3 维（典型 BA 重投影）
struct ReprojectionError {
  template <typename T>
  bool operator()(const T* const camera, const T* const point, T* residual) const {
    // ... 用 T 类型运算写残差公式，Ceres 自动带出导数
    residual[0] = ...; residual[1] = ...;
    return true;
  }
};

auto* cost = new ceres::AutoDiffCostFunction<ReprojectionError, 2, 9, 3>(
    new ReprojectionError(observed_x, observed_y));
两个高频坑

① 常量要写成 T(10.0) 而不是裸 10.0；② 对 Jet 类型要用 ceres::sin/cos/exp 而不是 std::sin。否则自动微分失效或编译报错。

4.4 NumericDiffCostFunction — 数值微分

template<typename CostFunctor, NumericDiffMethodType method = CENTRAL, int kNumResiduals, int... ParameterBlockSizes> class NumericDiffCostFunction;

当残差函数无法模板化（比如内部调用了不可改的第三方库）时用数值差分近似导数。方法可选 CENTRAL（中心差分，默认更准）、FORWARD、RIDDERS。仿函数用普通 double 写即可。

数值微分写法
struct CostFunctor {
  bool operator()(const double* const x, double* residual) const {
    residual[0] = 10.0 - x[0];
    return true;
  }
};
auto* cost = new ceres::NumericDiffCostFunction<CostFunctor, ceres::CENTRAL, 1, 1>(
    new CostFunctor);
代价：精度受步长影响、比自动微分慢（要多次求值）。能用自动微分就别用它。

4.5 DynamicAutoDiffCostFunction — 运行时维度

当参数块数量在编译期不确定（如 IMU 预积分窗口长度可变）时使用。仿函数的 operator() 接收指针数组和计数。复杂度最高，普通场景用不到。

4.6 四种方式怎么选

方式导数来源精度速度推荐度
AutoDiffCostFunction自动微分机器精度快⭐⭐⭐⭐⭐ 首选
SizedCostFunction手写解析精确最快⭐⭐⭐ 性能瓶颈时
NumericDiffCostFunction数值差分近似慢⭐⭐ 无法模板化时
DynamicAutoDiffCostFunction自动微分机器精度较快⭐⭐ 动态维度时

05LossFunction：鲁棒损失

默认情况下，残差越大惩罚按平方增长，离群点会把结果拽歪。给残差套一个鲁棒损失函数，让大残差的影响"封顶"，就能抗离群点。作为 AddResidualBlock 的第二个参数传入。

类损失 ρ(z)特点 / 用途
TrivialLossz²标准平方损失（等价不传），无鲁棒性。
HuberLoss(a)|z|≤a: z²；否则 a(2|z|−a)小残差按平方、大残差线性增长。最常用，温和。
CauchyLoss(a)a²·log(1+(z/a)²)大残差影响回落，抑制离群点更激进。经典选择。
SoftLOneLoss(a)2(√(1+z²/a)−1)类似 Huber 但处处可导平滑。
ArcTanLoss(a)a²·arctan²(z/a)更强抑制，用于极端离群点。
ScaledLoss(raw, a, ownership)a·ρ(z)给任意损失再乘一个尺度系数。
使用鲁棒损失
// 每个残差块套 Cauchy 损失，尺度参数 a=1.0
problem.AddResidualBlock(
    new ceres::AutoDiffCostFunction<CostFunctor, 1, 1>(new CostFunctor),
    new ceres::CauchyLoss(1.0),   // ← 这里；不鲁棒就传 nullptr
    &x);

// 组合：把 Huber 损失整体缩放 0.5
auto* loss = new ceres::ScaledLoss(new ceres::HuberLoss(2.0), 0.5,
                                   ceres::TAKE_OWNERSHIP);
尺度参数 a 很关键

a 要和你的典型残差量级匹配。a 远大于残差 ≈ 没加鲁棒性；a 太小则正常点也被当离群点。建议先跑一遍普通最小二乘，看看典型残差大小再定 a。

底层接口（了解即可）

所有损失都继承 LossFunction，核心方法 Evaluate(double s, double rho[3])：输入平方残差 s=z²，输出 ρ(s)、ρ′(s)、ρ″(s) 三个值。一般无需自己实现。

06Manifold：流形约束

有些参数自带几何约束：四元数必须单位长度、角度按 2π 循环。直接当普通 double 更新会破坏约束。Manifold 让参数更新"贴着约束面走"，更新后仍合法。Ceres 2.2 起用它取代旧的 LocalParameterization。

6.1 内置流形类

类Ambient / Tangent用途
EigenQuaternionManifold4 / 3Eigen 四元数，内存布局 [x,y,z,w]，保证单位长度。最常用。
QuaternionManifold4 / 3四元数，布局 [w,x,y,z]。
AngleManifold1 / 1角度，处理 2π 周期性，避免 ±π 跳变。
SphereManifold<k>k / k−1k 维单位球面。
ProductManifold<A, B, ...>拼接把多个流形组合成一个（如位置+旋转）。
位姿：3D 平移（欧氏）+ 四元数旋转（流形）
double pose[7];  // [x, y, z, qx, qy, qz, qw]
problem.AddParameterBlock(pose, 7);
problem.SetManifold(pose,
    new ceres::ProductManifold<
        ceres::EuclideanManifold<3>,
        ceres::EigenQuaternionManifold>());

6.2 Manifold 基类接口（自定义流形时实现）

class Manifold { virtual int AmbientSize() const = 0; // 参数在内存中的维度 virtual int TangentSize() const = 0; // 切空间（自由度）维度 virtual bool Plus(const double* x, const double* delta, double* x_plus_delta) const = 0; virtual bool Minus(const double* x, const double* y, double* delta) const = 0; // 还有 PlusJacobian / MinusJacobian 等，可用自动微分版基类简化 };

Plus 是关键：给定当前值 x 和切空间增量 delta，算出更新后的值并投影回流形。AmbientSize 与 TangentSize 不同的正是流形的意义——比如单位四元数用 4 个数存、只有 3 个自由度。

何时必须用

只要参数属于流形（单位四元数、旋转矩阵、单位向量、角度周期），就必须声明，否则优化过程中约束会被破坏，结果无物理意义。Ceres 官方强烈建议用 Manifold 而非旧的 LocalParameterization。

07Solver::Options：求解配置全解

这是旋钮最多的一个结构，按功能分组看就不乱了。绝大多数场景只改前两组就够了，其余保持默认。

7.1 迭代与收敛控制（最常用）

字段默认说明
max_num_iterations50最大迭代次数。到点就停，无论是否收敛。
max_solver_time_in_seconds1e6最长求解时间，超时停止。实时系统常设。
function_tolerance1e-6目标函数相对变化小于它就认为收敛。
gradient_tolerance1e-10梯度最大值小于它认为收敛。
parameter_tolerance1e-8参数相对变化太小认为收敛。
num_threads1线程数。大问题开多线程加速。

7.2 最小化器与信赖域

字段可选值 / 默认说明
minimizer_typeTRUST_REGION(默认)、LINE_SEARCH整体优化策略。
trust_region_strategy_typeLEVENBERG_MARQUARDT(默认)、DOGLEG信赖域步长策略（LM 就是之前推导的那个）。
initial_trust_region_radius1e4初始信赖域半径。
max_trust_region_radius1e16最大半径。

7.3 线性求解器（按问题规模选）

这是影响性能最大的选择。linear_solver_type 的取值与适用场景（已对照官方 FAQ 核实）：

取值适用场景
DENSE_QR（默认）小规模（几百个参数）或稠密问题。试手首选。
DENSE_NORMAL_CHOLESKY小规模稠密，通常比 QR 快。
SPARSE_NORMAL_CHOLESKY一般稀疏问题。需 SuiteSparse / CXSparse 等。
DENSE_SCHURBundle Adjustment，约百台以内相机。
SPARSE_SCHUR更大规模 BA，Schur 补稀疏时。
ITERATIVE_SCHUR数千相机以上的大 BA，或没有稀疏 Cholesky 库时。
CGNR共轭梯度，超大规模稀疏。
典型配置
ceres::Solver::Options options;
options.linear_solver_type = ceres::SPARSE_SCHUR;      // BA 问题
options.preconditioner_type = ceres::SCHUR_JACOBI;    // ITERATIVE_SCHUR 时配预条件
options.trust_region_strategy_type = ceres::LEVENBERG_MARQUARDT;
options.max_num_iterations = 100;
options.num_threads = 8;
options.minimizer_progress_to_stdout = true;          // 打印每步日志
中小问题的性能开关

对中小规模问题，设 options.use_explicit_schur_complement = true 常能明显提速。没有稀疏 Cholesky 库时，ITERATIVE_SCHUR + SCHUR_JACOBI 预条件是很好的替代。

7.4 日志、调试与回调

字段说明
minimizer_progress_to_stdouttrue 时每步打印 cost、梯度、步长、信赖域半径等。
logging_to_stdout是否把 Ceres 的日志输出到 stdout。
check_gradientstrue 时用数值微分校验解析/自动微分的雅可比，调试神器。
numeric_derivative_relative_step_size梯度校验用的相对步长。
update_state_every_iteration每步都更新参数值，配合 IterationCallback 观察中间状态。
callbacks迭代回调，可在每步插入自定义逻辑（如记录轨迹、提前终止）。
调试导数正确性

怀疑自己雅可比写错时，打开 options.check_gradients = true，Ceres 会用数值微分逐项比对，误差大就会报警。这是排查"收敛异常"的第一招。

08Solver::Summary：读懂求解结果

求解完成后，Summary 告诉你"到底成没成功、花了多久、卡在哪"。诊断问题第一时间看它。

8.1 两个报告函数

std::string BriefReport() const; // 一行摘要 std::string FullReport() const; // 完整报告：各阶段耗时、迭代表
输出报告
ceres::Solve(options, &problem, &summary);
std::cout << summary.BriefReport() << "\n";
std::cout << summary.FullReport()  << "\n";

8.2 常用字段

字段说明
IsSolutionUsable()最重要：解是否可用。求解后先判断它，再看具体数值。
termination_type终止原因枚举，见下表。
initial_cost / final_cost初始 / 最终目标函数值。final 明显下降才说明优化有效。
num_iterations实际迭代次数。
num_successful_steps / num_unsuccessful_steps成功 / 失败的迭代步数，失败多说明信赖域太激进。
total_time_in_seconds总耗时。另有 solver_time、evaluation_time、linear_solver_time 分项。

termination_type 的取值：

枚举含义
CONVERGENCE正常收敛，最理想。
NO_CONVERGENCE达到迭代/时间上限但未收敛，可能需要放宽上限或调初值。
FAILURE求解失败（数值问题等），要查模型和初值。
USER_SUCCESS用户回调主动成功终止。
DID_NOT_RUN求解器根本没运行（问题为空等）。
规范的求解后检查
if (!summary.IsSolutionUsable()) {
  std::cerr << "求解失败：\n" << summary.FullReport();
  return -1;
}
std::cout << "cost: " << summary.initial_cost
          << " -> " << summary.final_cost << "\n"
          << summary.BriefReport() << std::endl;
性能诊断起点

官方明确建议：排查 Ceres 的运行速度和收敛问题时，第一步就是看 Summary::FullReport() 的输出——它列出了每一迭代的 cost 变化、梯度范数、步长、信赖域比值和各阶段耗时，能快速定位瓶颈。

09综合示例：把 API 串成一个完整程序

下面是一个曲线拟合 y = e^(mx+c) 的完整可编译程序，把前面所有核心 API 都用上了——自动微分代价函数、Problem 建模、Solver 配置、Summary 诊断。可以直接拿去编译运行。

curve_fit.cc · 完整可运行
#include "ceres/ceres.h"
#include <iostream>
#include <vector>

// 1) 定义自动微分代价函数：残差 = 预测值 - 观测值
struct ExponentialResidual {
  ExponentialResidual(double x, double y) : x_(x), y_(y) {}
  template <typename T>
  bool operator()(const T* const m, const T* const c, T* residual) const {
    residual[0] = ceres::exp((*m) * T(x_) + (*c)) - T(y_);
    return true;
  }
 private:
  const double x_, y_;
};

int main() {
  // 观测数据 (x, y)
  const double data[] = {0,1.1, 1,1.7, 2,2.0, 3,2.6, 4,3.2, 5,3.5};

  // 2) 参数初值
  double m = 0.3, c = 0.0;

  // 3) 构建 Problem：每个观测点加一个残差块，共享参数 m、c
  ceres::Problem problem;
  for (int i = 0; i < 12; i += 2) {
    ceres::CostFunction* cost =
        new ceres::AutoDiffCostFunction<ExponentialResidual, 1, 1, 1>(
            new ExponentialResidual(data[i], data[i+1]));
    problem.AddResidualBlock(cost, nullptr, &m, &c);  // nullptr=普通平方损失
  }

  // 4) 配置求解器
  ceres::Solver::Options options;
  options.linear_solver_type = ceres::DENSE_QR;
  options.minimizer_progress_to_stdout = true;
  options.max_num_iterations = 100;

  // 5) 求解
  ceres::Solver::Summary summary;
  ceres::Solve(options, &problem, &summary);

  // 6) 检查结果、输出
  std::cout << summary.BriefReport() << std::endl;
  if (summary.IsSolutionUsable())
    std::cout << "m = " << m << ", c = " << c << std::endl;
  return 0;
}
逐段对应

① 就是第 04 章的 AutoDiffCostFunction：模板 operator() + T(…) / ceres::exp。② 参数初值给个合理猜测。③ 第 03 章的 AddResidualBlock，每个点一个残差、共享 m 和 c。④ 第 07 章 Options，小规模用 DENSE_QR。⑤⑥ 第 02 章 Solve + 第 08 章 Summary。任何 Ceres 程序都是这 6 步的排列组合。

10.2 新手高频错误

编译

找不到 Ceres 头文件

CMake 里漏了 find_package(Ceres REQUIRED) 或没有 target_link_libraries(... ${CERES_LIBRARIES})。

编译

C++ 标准太低

Ceres 2.x 需要 C++14 及以上。CMake 里设 set(CMAKE_CXX_STANDARD 14)。

自动微分

常量没写 T(...)

T(10.0) - x[0] 写成 10.0 - x[0]，Jet 运算失效。

自动微分

用错数学函数

对 Jet 用 std::sin 会编译失败，要用 ceres::sin。

建模

传值不传地址

AddResidualBlock(..., x) 传的是值副本，求解器改不到原变量。必须 &x。

初始化

初值太离谱不收敛

非线性优化依赖初值。给个合理初值，或用多初值重试。看 Summary 诊断。

维度

模板尺寸写错

AutoDiffCostFunction<F, 2, 9, 3> 三个数依次是残差维、各参数块维，写错直接崩溃。

流形

四元数内存布局

Eigen 是 [x,y,z,w]（实部最后），构造函数是 (w,x,y,z)，Ceres 操作裸指针时极易搞混。

10.3 版本提示

LocalParameterization 已弃用

Ceres 2.2.0 起，LocalParameterization、SetParameterization() 被弃用，改用 Manifold / SetManifold()。老项目代码里若看到前者，就是旧版写法。内置类也相应从 QuaternionParameterization 变为 EigenQuaternionManifold。
