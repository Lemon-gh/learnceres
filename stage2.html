01安装环境

Ceres 依赖 Eigen、glog，新版本还依赖 Abseil。最省事的是用包管理器一键安装。

Ubuntu / Debian

终端
sudo apt update
sudo apt install -y cmake g++ libceres-dev
# 顺带装 glog、eigen（多数情况 libceres-dev 会带依赖）
sudo apt install -y libgoogle-glog-dev libeigen3-dev

Windows（推荐 vcpkg）

PowerShell
git clone https://github.com/microsoft/vcpkg
.\vcpkg\bootstrap-vcpkg.bat
.\vcpkg\vcpkg install ceres:x64-windows
# CMake 时加参数：-DCMAKE_TOOLCHAIN_FILE=.../vcpkg.cmake

conda（跨平台，最省心）

终端
conda install -c conda-forge ceres-solver
conda install -c conda-forge cmake cxx-compiler
验证安装

能找到 CeresConfig.cmake 就说明装好了。它在 /usr/lib/cmake/Ceres（Linux）或 vcpkg 的 share/ceres 下。

02写代码

建一个目录，放入两个文件。完整代码来自官方教程：

main.cc · 求 ½(10−x)² 的最小值
#include "ceres/ceres.h"        // Ceres 核心头文件
#include 

struct CostFunctor {            // 代价函数：残差怎么算
  template <typename T>        // 模板：支持自动微分
  bool operator()(const T* const x, T* residual) const {
    residual[0] = T(10.0) - x[0];
    return true;
  }
};

int main() {
  double x = 0.5;               // 待求参数 + 初值

  ceres::Problem problem;
  problem.AddResidualBlock(
      new ceres::AutoDiffCostFunction<CostFunctor, 1, 1>(),
      nullptr, &x);             // nullptr = 普通平方损失；&x 传地址

  ceres::Solver::Options options;
  options.minimizer_progress_to_stdout = true;
  ceres::Solver::Summary summary;
  ceres::Solve(options, &problem, &summary);

  std::cout << "x : 0.5 -> " << x << "\n";
  return 0;
}
CMakeLists.txt
cmake_minimum_required(VERSION 3.10)
project(hello_ceres)
set(CMAKE_CXX_STANDARD 14)
find_package(Ceres REQUIRED)
include_directories(${CERES_INCLUDE_DIRS})
add_executable(hello main.cc)
target_link_libraries(hello ${CERES_LIBRARIES})

06原理深挖：求解器内部怎么迭代

MATH + ANIMATION

Hello World 里 Solve() 一瞬间就把 x 从 0.5 变成 10。它内部并非沿梯度慢慢挪，而是用一套更聪明的办法。这章把它拆开看。

① 一阶近似：把非线性问题局部拉直

在当前点 x 附近，残差函数 r(x) 可以用一阶泰勒展开近似：r(x+Δx) ≈ r(x) + J·Δx，其中 J = ∂r/∂x 就是雅可比。于是最小化 ‖r+JΔx‖² 变成一个二次函数最小化问题。

② 高斯-牛顿：解出最优步长

对 ‖r+JΔx‖² 求 Δx 的导并令零 → (JᵀJ) Δx = −Jᵀ r 解线性方程得步长：Δx = −(JᵀJ)⁻¹ Jᵀ r

对比阶段 1 的梯度下降 Δx = −α∇cost（∇cost = Jᵀr）：高斯-牛顿多了个 (JᵀJ)⁻¹，相当于自动为每步调整了步长和方向——所以收敛快得多。

③ Levenberg-Marquardt：给高斯-牛顿加个"保险"

当 JᵀJ 接近奇异（病态）时，高斯-牛顿的步长会爆炸。LM 加一个阻尼项 μ：

(JᵀJ + μI) Δx = −Jᵀ r   μ 很小 → 接近高斯-牛顿（快） |  μ 很大 → 接近梯度下降（稳）

Ceres 默认就用 LM。它会根据这一步"实际下降量 vs 预测下降量"自动调 μ：走得好就减小 μ（更大胆），走得差就增大 μ（更保守）。这就是信赖域思想。

动画演示 · 阻尼 μ 如何改变每一步

目标函数 f(x)=½(10−x)²（即 Hello World）。紫点是高斯-牛顿路径，橙点是固定步长的朴素梯度下降。拖动 μ 看高斯-牛顿那一步被"压缩"到什么程度：μ=0 时一步到 10，μ 越大步子越小越稳。

紫(高斯-牛顿+μ) x=0.50   橙(梯度下降) x=0.50  |  目标 x=10
为什么默认选 LM

它兼具高斯-牛顿的快和梯度下降的稳：初值离得远时用大 μ 小步探路，接近最优时减小 μ 快速收敛。Ceres 的 Solver::Options::initial_trust_region_radius 等参数就是在调这套机制，一般不用手动改。
