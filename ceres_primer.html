01最小二乘直觉

假设有一堆观测点，你想找一条直线 y = mx + c 穿过它们。怎么算"最好的"那条线？做法是：对每个点，算出它到直线的残差 r（竖直距离），把所有残差平方后求和，让这个总和最小。

cost(m, c) = ½ ∑i ( yi − (m·xi + c) )² → 求使其最小的 m, c

这就是最小二乘。为什么平方？ 因为残差有正有负，直接相加会互相抵消；平方后都是正数，且大误差被惩罚得更重。为什么乘 ½？ 纯粹为了后面求导时平方的 2 能和它约掉，不影响最优解。

动手感受一下：拖动参数，看误差怎么变

观测点（带噪声） 当前拟合直线 残差（每个点的误差）
当前误差 cost = ½Σr²
0.00
目标：把 cost 降到最小 —— 这就是 Ceres 在做的事

映射到 Ceres 的术语

你现在理解的Ceres 里叫代码里对应
要调的参数 m, cParameterBlock（参数块）double m, c;
一个点的误差 yᵢ−(mxᵢ+c)Residual（残差）residual[0] = ...
误差平方和目标函数 / cost求解器内部计算
计算残差的那段逻辑CostFunction（代价函数）CostFunctor::operator()
一句话记住

Ceres 就是一个"高级调参器"：你告诉它残差怎么算，它自动帮你找到让残差平方和最小的参数值。"非线性"只是说残差和参数的关系不是直线那么简单。

02仿函数：把结构体当函数用

普通函数这样写：double f(double x) { return 10 - x; }。而"仿函数"（functor）是一个结构体，它定义了 operator()，于是可以像函数一样被调用：

functor_basics.cc
#include <iostream>
struct Minus {
  double operator()(double x) const { return 10.0 - x; }
};
int main() {
  Minus minus;                 // 先造一个对象
  std::cout << minus(3.0) << "\n";  // 像函数一样调用它 → 7
}

Ceres 为什么喜欢仿函数而不是普通函数？因为仿函数是对象，可以携带数据。比如拟合直线时，每个观测点的 xᵢ, yᵢ 不同，我们可以在构造对象时把它们存进去：

带状态的仿函数 · 这就是 Ceres 代价函数的雏形
struct LineResidual {
  LineResidual(double x, double y) : x_(x), y_(y) {}   // 观测点存进对象
  double operator()(double m, double c) const {
    return y_ - (m * x_ + c);                          // 残差
  }
 private:
  double x_, y_;
};
// 用法：LineResidual r(2.0, 5.1);  r(0.5, 1.0) → 某个残差值
要点

operator() 后面的 const 表示这个函数不修改对象自身。Ceres 的代价函数也都带这个 const。

03模板：一份代码，两种用途

现在把上面的仿函数改成模板：把具体的 double 换成类型参数 T。

template_basics.cc
template <typename T>
T minus(T x) { return T(10.0) - x; }

// 编译器会自动生成两个版本：
// minus<double>(3.0) → 7.0        普通算术
// minus<int>(3)    → 7           整数版本
int main() {
  std::cout << minus(3.0) << " " << minus(3) << "\n";
}

关键在 T(10.0)：把常量 10.0 也构造成类型 T。这样整个表达式都在 T 类型下运算。这一点在 Ceres 里至关重要。

这正是 Ceres 的自动微分原理

Ceres 会用两种类型来调用你写的模板残差函数：

  • T = double：普通计算，得到残差数值，用来评估"当前误差多大"。
  • T = Jet：Ceres 的特殊类型，运算时顺带把导数也算出来，用来告诉求解器"往哪个方向调参数能让误差变小"。

所以你只需要写一遍残差公式，导数 Ceres 全自动搞定。这就是官方教程 Hello World 里的写法：

Ceres 的标准代价函数写法
struct CostFunctor {
  template <typename T>                          // 模板！
  bool operator()(const T* const x, T* residual) const {
    residual[0] = T(10.0) - x[0];                 // 用 T(10.0) 而非 10.0
    return true;
  }
};
新手最容易犯的错

把 T(10.0) 写成裸的 10.0，或者在函数里调用普通 double 库函数（如 std::sin 用在 Jet 上要用 ceres::sin）。这会让自动微分失效或编译报错。

04指针与引用：让求解器改你的变量

Ceres 求解时会原地修改你传进去的参数变量。要做到这一点，必须传地址（指针），而不是传值。

pointer_basics.cc
#include <iostream>
void setToTen(double* p) { *p = 10.0; }   // p 是地址，*p 是那个变量本身

int main() {
  double x = 5.0;
  setToTen(&x);                            // &x 取 x 的地址传给函数
  std::cout << x << "\n";                 // 输出 10，x 被改了
}

如果你写成传值 setToTen(double p)，函数里改的只是副本，外面的 x 不会变。Ceres 内部和这里完全一样：

Ceres 里传的就是局部变量的地址
double x = 0.5;                       // 待求参数，初值 0.5
problem.AddResidualBlock(cost_function, nullptr, &x);  // 传 &x
Solve(options, &problem, &summary);
// 求解后 x 已经被就地改成了 10 附近的值
符号含义在 Ceres 中的例子
&x取变量 x 的地址AddResidualBlock(..., &x) 传参数
*p访问指针 p 指向的那个变量残差函数里 x[0] 本质也是指针访问
T* residual一个指针，用来"写回"结果residual[0] = ... 把算出的残差写进去
类比

把 &x 想象成把你家的地址交给别人，他才能到你家里改东西；传值则像是只给了他你家的一份照片，他改照片不影响你家。

05CMake 最小工程

CMake 是 C++ 项目的构建工具：你写一份 CMakeLists.txt 描述"要用哪些库、编译哪些文件"，它帮你生成编译命令。小白只需掌握下面这个最小模板。

项目结构
my_ceres/
├── CMakeLists.txt
└── main.cc
CMakeLists.txt
cmake_minimum_required(VERSION 3.10)   # 声明 cmake 最低版本
project(my_ceres)                      # 项目名

set(CMAKE_CXX_STANDARD 14)             # 用 C++14 编译

find_package(Ceres REQUIRED)           # 找到已安装的 Ceres

add_executable(main main.cc)           # 用 main.cc 生成可执行文件 main
target_include_directories(main PRIVATE ${CERES_INCLUDE_DIRS})
target_link_libraries(main ${CERES_LIBRARIES})  # 链接 Ceres 库

编译运行三步

mkdir build && cd build # 建一个构建目录 cmake .. # 生成构建文件 make # 编译 ./main # 运行
报错先查这里

find_package(Ceres REQUIRED) 找不到 Ceres，是因为它没装好或 CMake 不知道去哪找。这是新手 90% 编译失败的根源，跟你的算法代码无关。

06逐行拆解 Hello World

现在把四块基础串起来。下面是完整的 Ceres 最小示例，逐行注释。

main.cc · 求 ½(10−x)² 的最小值
#include "ceres/ceres.h"        // ① 引入 Ceres
#include <iostream>

struct CostFunctor {            // ② 仿函数：定义残差怎么算
  template <typename T>        // ③ 模板：支持 double / Jet 两种调用
  bool operator()(const T* const x, T* residual) const {
    residual[0] = T(10.0) - x[0];//    残差 r = 10 - x，写回 residual
    return true;                //    返回 true 表示计算成功
  }
};

int main() {
  double x = 0.5;               // ④ 待求参数，初值 0.5（会被原地修改）

  ceres::Problem problem;       // ⑤ 创建一个优化问题
  problem.AddResidualBlock(     // ⑥ 往问题里加一个残差块
      new ceres::AutoDiffCostFunction<CostFunctor, 1, 1>(), // 自动微分
      nullptr,                  //    损失函数：nullptr = 普通平方损失
      &x);                      //    要优化的参数：传地址！

  ceres::Solver::Options options;// ⑦ 求解器配置
  options.minimizer_progress_to_stdout = true; // 打印迭代过程
  ceres::Solver::Summary summary;//    求解结果报告
  ceres::Solve(options, &problem, &summary); // ⑧ 开跑！

  std::cout << x << "\n";      // ⑨ 输出：约等于 10
  return 0;
}
1
引入头文件：ceres/ceres.h 是核心头文件，包含了 Problem、Solver 等所有需要的类。
2
代价函数：一个结构体，告诉你"残差怎么算"。Ceres 会反复调用它来评估当前参数的好坏。
3
模板 + T(10.0)：让同一份残差公式既能算数值又能算导数。AutoDiffCostFunction 就靠这个工作。
4
参数 + 初值：求解器从这里出发，一步步把 x 调整到最优。给个合理初值更容易收敛。
5
Problem：装着所有残差块和参数的容器，就是要解的整个优化问题。
6
AddResidualBlock：把一个代价函数挂到问题上。模板参数 <CostFunctor, 1, 1> 分别是"残差块类型、残差维度、参数维度"。
7
Options / Summary：配置求解过程 + 接收求解报告。打开 progress 能看到每步 cost 怎么降。
8
Solve：真正开始优化。跑完后 x 已经被改成了最优值。

你已经看懂了

如果你能讲清楚这 9 步在干什么，恭喜——Ceres 所有复杂示例（曲线拟合、BA、SLAM）都只是把第 ② 步的残差公式换掉、把第 ⑥ 步的残差块多加几个，骨架完全不变。

07检验自己

学完这一页，试着不看答案回答这几个问题。答得上来，基础就算打好了：

  1. 最小二乘中的"残差"是什么？为什么要把它平方？
  2. 仿函数和普通函数相比，多了什么能力？（提示：能存数据）
  3. 为什么 Ceres 的代价函数要写成 template<typename T>？如果写成固定 double 会失去什么？
  4. AddResidualBlock(..., &x) 里为什么是 &x 而不是 x？
  5. AutoDiffCostFunction<CostFunctor, 1, 1> 的两个 1 分别是什么意思？
点击展开参考答案
  1. 残差是预测值和观测值之差；平方是为了消除正负抵消并加重大误差的惩罚。
  2. 仿函数是对象，可以在成员变量里保存观测数据（如 xᵢ, yᵢ）。
  3. 为了让 Ceres 用 double 算残差、用 Jet 算导数；写死 double 就没法自动求导，得自己手推雅可比。
  4. 传地址才能让求解器原地修改 x；传值只改副本。
  5. 第一个 1 是残差维度（输出几个残差），第二个 1 是参数块维度（这个参数有几个数）。
